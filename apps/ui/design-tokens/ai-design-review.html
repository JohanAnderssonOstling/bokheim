MediumSource + calculated colors

Keyboard focus is too close to the background

The shared button draws focus as a one-pixel inset border. For the neutral treatment it uses the same quiet rule color as decorative boundaries. Against the warm light page that color pair is about 1.67:1; cool light is about 1.77:1. These are color calculations, not a full accessibility certification.

Recommendation. Give keyboard focus its own clearly visible treatment, for example a two-pixel accent outline with space around it. Retain the existing solid selected state, so current selection and keyboard focus remain distinct.

apps/components/src/button.rs, focus overlay near line 292; theme/palettes.rs, rule and surface colors. Filled/selected controls use another branch and need separate checks.

MediumObserved catalog + source

Some category names lose too much meaning to truncation

Even at 1440px, the catalog’s three-column cards truncate labels such as “Formats & Coll…” and “Teaching & Lea…”. The category list shares a fixed card with large cover previews. Partial cover previews look intentional and can suggest more content; losing the category’s distinguishing words is the more important cost.

Recommendation. Keep the colored section bands. Revisit the width balance between the category list and previews, allow a little more title space where it helps, and expose complete names on keyboard focus and hover. Check longer names and larger UI fonts before changing density globally.

Mostly specific. A few phrases sound generic.

My honest assessment: bokheim.se does not strongly look AI-designed. The familiar slogans and regular feature-section rhythm can give a mild template impression. They are weak signals, outweighed by a consistent reading-app identity and real demonstrations.

Weak signalRepeated page rhythm

The screenshot section follows a very regular template

Folder structure, categorization, catalog and narration arrive in a similar sequence: heading, explanatory line, large rectangular demonstration. In a long scroll, that repetition can resemble a quickly assembled landing-page template. It also gives the visitor a predictable reading order, so repetition is not automatically a defect.

Recommendation. If you want less template-like pacing, vary one transition rather than redesigning every section. For example, give the folder screenshot a short concrete caption about the folders shown, and let the narration sample lead its section. Avoid adding decorative cards just to create variety.

Deferred GPUI web accessibility work
HighObserved in Firefox + source

The web interface is largely absent from the accessibility tree

The running web app displayed navigation, buttons and settings, but Firefox’s accessibility snapshot contained only a textbox named “Text input”. Further inspection confirms a GPUI web-backend limitation: accessibility adapter initialization is excluded for WebAssembly, and WebWindow does not implement the accessibility adapter hooks. This has a substantial user impact, but belongs to framework/platform work rather than an ordinary application UI fix.

Recommendation. Treat this as a GPUI web-platform capability gap. It needs a browser accessibility bridge that exports controls, names, values and states and routes assistive actions back into GPUI. Adding labels to app controls alone cannot repair the missing bridge. Scope this separately from routine UI polish and validate with screen readers. WebAssembly itself does not prevent accessible interfaces.

Browser observation: body.aria_snapshot() → - textbox "Text input". Framework evidence: GPUI-Fork/crates/gpui/src/window.rs near 1604 excludes adapter initialization with cfg(not(target_family = "wasm")); gpui_web/src/window.rs has no adapter-hook implementations; gpui/src/platform.rs supplies no-op defaults. AccessKit lists its web adapter as planned. Native screen-reader behavior was not tested. The local Button implementation does set roles, but icon-only wrappers supply a tooltip rather than a label; also check their accessible names and disabled states when bridging them.
