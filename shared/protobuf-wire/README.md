# Protobuf contracts

HTTP and WebSocket boundaries use `protobuf_wire::typed` (re-exported as
`sync_common::http`). Protocol 34 replaces the generic Serde value tree with
explicit endpoint messages. Clients and servers must be upgraded together;
there is no fallback decoder for earlier HTTP formats.

Each body contains an `Envelope`: field 1 is the HTTP version and field 2 is the
endpoint's protobuf message. Responses returning a list wrap repeated messages
in field 1. The empty request is an empty message inside the envelope. HTTP
media-type checks continue to enforce the same version.

`proto/sync.proto` and `proto/account.proto` describe the messages. Generate them
and their Rust message definitions, domain conversions, admission schemas, and
borrowed encoders with:

```sh
python3 scripts/generate-http-contracts.py
```

The generator's field order determines protobuf field numbers. Changing the HTTP
contract requires reviewing and bumping `protocol.json`. Notification handling
is in `shared/sync-common/src/http_notifications.rs`.

Encoding writes borrowed strings and byte buffers directly into the final body;
it does not construct protobuf copies of the domain messages. Size calculation
uses the same fields without copying or serializing payloads. Decoding first
scans borrowed bytes against the endpoint schema, then constructs typed prost
messages and moves their buffers into the domain objects. It neither builds a
generic value tree nor re-encodes the received message for canonical comparison.

The scan checks these limits before prost allocates messages or collections:

- The caller's total body-byte limit.
- Per-field byte lengths and integer ranges.
- Per-field occurrence counts, including rejection of duplicate singular fields.
- At most 131,072 fields across the entire message and 32 nested message levels.
- No unknown fields or mismatched protobuf wire types.

Batch limits are 1,000 submitted mutations, 4,096 manifest/presence entries, and
16 thumbnail entries. Each thumbnail buffer is at most 4 MiB. Ordinary strings
are at most 4 KiB; state keys are at most 1 KiB. Top-level list responses are
limited to 4,096 messages. The sync pull budget is 4 MiB including the conservative
per-entry delivery allowance, which also keeps the page under 4,096 entries.
The push budget is also 4 MiB for the complete exchange request, including
mutation wrappers, IDs, the protocol envelope, and space for the largest valid
cursor. A single stored payload must leave room for its address bytes and the
1 KiB delivery allowance within both push and pull budgets. State encoding
checks that allowance before allocating the output buffer; the relay rejects
undeliverable submissions as invalid payloads before storing them. The HTTP
exchange endpoint enforces the complete request-byte limit as well.
These bounds are part of the contract even where standard protobuf cannot
express them. The scan bounds structural expansion; it is not an exact heap-byte
accounting system, and request concurrency and body limits still matter.

Stored sync payloads remain opaque to HTTP and the relay. Their version belongs
to `library_replica::storage::VERSION` (34), independently of the HTTP version.
They now use typed protobuf too, including annotations, navigation, PDF metadata,
and the nested book-record codec. Their schema and conversions live under
`client/library-backend/crates/library-replica/src/storage` and are generated by
`scripts/generate-state-contracts.py`. The stored-state scan permits at most
524,288 fields, 96 message levels, and a 4 MiB body; the individual repeated-field
and byte limits are specified in the generated schema. Multiple alternatives of
a protobuf oneof are rejected before decoding.

Normal replicas accept only the current storage version. The offline
`library-cloud-upgrade` tool converts legacy generic payloads, archives the old
rows, and changes the sync-history generation in one transaction. No database
migration is run automatically by the client or server. Local bincode storage
is unchanged. Persisted format changes must still be reviewed independently of
HTTP changes.

Stored-state encoding writes borrowed domain fields directly into the final
buffer, including embedded book records and formatted reading positions.
Size calculations use the same field traversal with a counting encoder, so
navigation limits do not construct temporary protobuf messages. Before domain
validation or output allocation, that pass checks the decoder schema's nesting,
total field count, per-field counts, byte lengths, and scalar ranges. It stops
at the first exceeded limit and returns an error identifying the limit.
Navigation and enriched TOC sizing also stop at their 512 KiB budgets.
Prost message types remain the owned decoding representation.

Unreleased storage version 34 encodes PDF pages as numeric columns, broadcasting
uniform values and omitting all-zero rotations. Borrowed column encoding writes
little-endian f32 dimensions and u16 rotations directly into the final buffer.
Bounded byte fields and a bounded page count limit decoding; column cardinality
is validated before allocating the expanded page list.
