EPUB reader · static audit

Good boundaries, a few consequential leaks.

The reader is not fundamentally unidiomatic. Its focus handling, typed events, search cancellation, and renderer boundary are strong. The remaining important mistakes are narrower: delayed annotation mutations can lose edits, and several renderer projections are not kept synchronized. EPUB media-overlay audio was removed after this audit.

01 · Correctness

The most important mistakes affect lifetime and ordering.

1

EPUB media-overlay audio had an incomplete lifetime

Removed

This finding is retained as the reason for the change. The EPUB audio state, toolbar affordance, backend API, polling tasks, kira dependency, and feature wiring have now been removed. The separate audiobook player is unchanged.

2

Persist-then-apply can lose rapid annotation edits

High

Each save clones the current stored annotation, writes it on the persistence worker, and updates local state only after success. Two quick edits therefore start from the same stale snapshot. A colour click followed by a style click can cause the later write to restore the old colour. Creation and deletion have the same delayed-interaction shape.

epub/state.rs:210–345
Click Bluecaptures Yellow + Highlight
→
Click Underlinecaptures Yellow + Underline
→
Writes finishBlue is overwritten by stale Yellow
Prefer optimistic local mutation: update the model and renderer synchronously, then enqueue the durable write. Roll back or surface an error if persistence fails. Filesystem speed is not the core issue; state ordering is.
3

The toolbar's progress projection is not refreshed

Medium

ReadingProgress updates self.progress and records persistence, then returns false. The toolbar owns a copied ToolbarModel, so its percentage remains stale until an unrelated toolbar event pushes a new model.

02 · Navigation projections

TOC and title state are not total mappings.

4

TOC fallback selects an arbitrary entry

Medium

TocState::link_at performs its fallback by taking the first entry for a document from a HashMap. That order is deliberately unspecified. Because the reader does not install the publication's TOC anchors into the renderer's anchor filter, the reported anchor can also be an ordinary markup ID rather than a TOC anchor. When no entry matches, active_link becomes empty but the tree's selected item is not cleared.

epub/toc.rs:46–51 · epub/state.rs:368–381
Keep resolved TOC entries in publication order, install their anchor strings in HtmlViewCore, choose the nearest preceding entry, and explicitly set the tree selection to None when there is no active entry.
5

A missing document title leaves the previous title stuck

Medium

The event handler matches only TitleChanged(Some(title)). Moving from a titled spine item to an untitled one emits TitleChanged(None), which falls through and preserves the previous chapter title.

epub/state.rs:359–367
epub/state.rsillustrative change
RendererEvent::TitleChanged(Some(title)) => {
RendererEvent::TitleChanged(title) => {
    let title = title.clone().unwrap_or_else(|| self.book_title.clone());
    if self.title == title { false } else {
        self.title = title;
        true
    }
}
03 · GPUI rendering

The render tree is mostly observational, but not fully isolated.

6

Render changes the native window title

Low

window.set_window_title runs on every reader render. It is idempotent, but still a platform mutation inside a method that should describe current UI. Set it during activation or when the title actually changes. The debug render counter is also a mutation, but is a reasonable instrumentation exception.

epub/render.rs:217–222
7

The toolbar entity is an ownership boundary, not complete render isolation

Low

In GPUI-Fork, notifying a rendered child marks its ancestor view path dirty. The reader shell therefore renders when the toolbar changes. Both the toolbar and renderer are embedded as ordinary, uncached entities. HtmlView::render is small and its painter has internal caches, so this is primarily an inaccurate architectural claim—not a catastrophic cost.

8

Annotation placement duplicates renderer layout policy

Low

The shell recomputes fitted column count using its own gap, scaling, width, and rounding assumptions. A future renderer change can silently place the editor over the wrong column. The renderer should expose its actual laid-out column geometry as observable state.

epub/render.rs:25–39

06 · Recommended order

Fix user-visible correctness before optimizing boundaries.

Make annotation state optimistic and orderedMutate locally first, persist second, and define rollback/error behavior.
Repair progress and title projectionsSmall, high-confidence event-handler fixes.
Make TOC position mapping orderedInstall TOC anchor filters and clear stale tree selection.
Move the window-title side effectFinish the observational-rendering work.
Measure before adding cached entity elementsThe renderer already has paint caches; verify shell invalidation cost before complicating layout.
Delete dead projections and loading machineryReduce the number of states future work must keep synchronized.
