browser-ui · implementation plan

Change less code, make the boundaries sharper.

The codebase does not need a rewrite. I recommend six focused changes: remove behavior from rendering, simplify invalidation, make focus semantic, own user-visible tasks, reduce paginator measurement cost, and introduce stateless components selectively.

01 · Applied

02 · Applied

03 · Focus applied; actions deferred

Keep local keyboard handling and make focus deliberate.

The existing raw arrow-key handling is compact and appropriately local to the browse page. Converting it into actions would add machinery without a current remapping, menu or command-palette requirement. The useful part of this step is explicit focus ownership.

04 · Behavioral improvement

Store tasks the user can still observe or repeat.

Detached tasks are safe because GPUI passes a weak entity, but safety is not the only lifecycle question. Trash operations should disable their originating controls and prevent duplicate commands.

IdleControls enabled; no mutation task.
→
Busy(target)Store task, disable matching controls, notify.
→
CompleteClear task and busy state; refresh or show error.

05 · Measure first

Reduce paginator work without weakening its model.

The custom element is appropriate. The expensive part is candidate evaluation: intrinsic child trees are constructed for candidate widths and the accepted page is constructed again. First remove render side effects; then profile resize, initial layout and data replacement before changing geometry policy.

Illustration · where repeated work occurs
Low-risk optimization

Persist intrinsic heights with the paginator data, keyed by child, width and rem size. Replacing groups naturally discards the cache.

Higher-risk optimization

Rank candidates solely from declared sizing and render only the winner. Faster, but may change packing when children are shorter than their maximum.

widgets/paginatorillustrative persistent cache
@@ struct PaginatorData
+    intrinsic_heights: RefCell<HashMap<IntrinsicMeasurementKey, Pixels>>,
@@ measure_intrinsic_row_height
-    *intrinsic_heights.entry(key).or_insert_with(|| measure_child(...))
+    if let Some(height) = self.data.intrinsic_heights.borrow().get(&key) {
+        return *height;
+    }
+    let height = measure_child(...);
+    self.data.intrinsic_heights.borrow_mut().insert(key, height);
+    height
This diff is intentionally illustrative, not a first commit. Cache placement and borrowing should be chosen after profiling. The geometry selection cache already avoids most repeated candidate work when bounds and revision remain stable.
06 · Low-priority polish

Use RenderOnce for concepts, not fragments.

The code has many builder helpers. Most are fine. Promote only units that have a name, props, repeated structure and value in the inspector—such as a review metadata field, a settings row variant, or browse options as a whole.

conceptual component extractionnot a blanket rewrite
-fn metadata_field(theme: BrowserTheme) -> Div { ... }
+#[derive(IntoElement)]
+struct MetadataField {
+    value: SharedString,
+    emphasis: MetadataEmphasis,
+    theme: BrowserTheme,
+}
+impl RenderOnce for MetadataField { ... }

Leave one-line spacing/layout helpers as functions. An entity would be wrong here because the component has no durable state; RenderOnce simply gives the stateless widget identity and an explicit prop surface.

Suggested sequence

Six small reviewable changes.

1 · render-purityRemoved card preparation and search construction from Render; review covers now prepare after visible prepaint.applied
2 · invalidationRemoved paginator parent observers and helper-level duplicate notify.applied
3 · browse-focusExplicit route focus applied; local arrow handling retained to avoid unnecessary action machinery.applied
4 · trash-lifetimeStore operation tasks and expose busy state to controls.behavior
5 · measurementProfile first; add a persistent intrinsic cache only if supported.measure
6 · componentsExtract two or three coherent stateless widgets as examples.polish
Recommended stopping point: after steps 1–4, reassess the application before touching the paginator algorithm. Those changes clarify semantics and UX regardless of benchmark results; step 5 is justified only by evidence.
Scope: changes for apps/browser against the current local GPUI-Fork model. Render purity, invalidation cleanup and explicit browse focus are applied; action conversion is intentionally deferred and later sections remain proposals.
