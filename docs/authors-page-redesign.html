An index that files the same person under two letters

Authors is a fixed split: a filtered name list on the left, the selected author's books and a catalogue search on the right. The list is sorted by whichever spelling of a name happened to sort first — MIN(credited_name) — while the sort_name that exists for exactly this purpose is stored, read back, and never used.

Fourth in the series. Follows docs/hierarchy-page-redesign.html and docs/home-page-redesign.html.

What I'd build

A, and take B's header with it. A is the whole fix for the complaint the page actually earns — that you cannot find a name in it — and it needs no layout change and no new query beyond the ones the defects already force. B is the better long-term shape and the argument for it is consistency with Folders and Subjects, not this page's own failings; its header is worth stealing immediately regardless.

  1. Order and display the index by sort_name, falling back to the credited name; one identity, one entry, one letter.
  2. SELECT DISTINCT in get_book_cards_by_author, and render one count from one source.
  3. Virtualize the books pane — render_virtualized, as every other grid does.
  4. Letter dividers in the list and an A–Z jump rail beside it.
  5. Drop the avatar; right-set the count in its own column.
  6. Offer the two sorts the contract already defines.
  7. Collapse catalogue discovery behind a disclosure, fetched on expand and cached per author.
  8. Move the page's strings into the contracts, and its inline styling into components.

Not answered from the code

  • Is sort_name populated in practice? It is written from the EPUB's file-as when present. If most books omit it, the index needs a derived fallback — last token, or a name parser — and that choice decides whether A is a day or a week.
  • Should two spellings ever stay separate? author_identity already merges by normalized name; if the merge is trusted, the duplicate rows in the mockup are a display bug. If it isn't, the page needs a way to say "these are the same person".
  • Publication year for the shelf order. B and D order books by year; the by-author query orders by title, and I did not confirm a year column reaches BookCardRow at all.
  • Does anything still want the eager catalogue sweep? The module header says the availability pre-warm and its two filter toggles were dropped "until the structure settles". Directions here assume they do not come back.
